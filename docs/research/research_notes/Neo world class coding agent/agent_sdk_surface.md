# Claude Agent SDK / Claude Code / Codex SDK feature surface for a self-hosted headless engine (as of 2026-11-02)

Scope note: findings are from the official Claude Code docs (code.claude.com, read 2026-11-02), the npm registry, the `openai/codex` GitHub source, and two GitHub issues. Version anchors: the npm registry lists `@anthropic-ai/claude-agent-sdk` latest `0.3.316` (published 2026-10-31) and `@openai/codex-sdk` latest `0.166.0` (published 2026-11-01); Neo pins `0.3.291` and `0.145.0` in `package.json`. The SDK docs state that "the SDK version tracks the bundled Claude Code version. For example, SDK v0.3.191 bundles Claude Code v2.1.191" — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript), so `0.3.291` ≈ Claude Code `2.1.291`; everything below marked "v2.1.292+" or "v0.3.292+" is therefore NOT in Neo's pinned build. `developers.openai.com` could not be fetched from this session (network allowlist), so Codex semantics come from the SDK source only.

## 1. Sessions: resume, fork, tags, prewarm, state events, transcripts, cost/usage, rate limits, budgets

### Takeaway
The SDK now exposes a full session-management surface beyond `resume`: `forkSession`, `continue`, `resumeSessionAt`/`resumeDropsTurn`, `sessionId`, `persistSession`, an external `sessionStore` mirror, a `startup()` prewarm, standalone `listSessions/getSessionInfo/getSessionMessages/renameSession/tagSession/forkSession/deleteSession` helpers, `session_state_changed` events (opt-in via `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS=1`), rich result accounting (`modelUsage`, `permission_denials`, `terminal_reason`), `rate_limit_event`, and `maxTurns`/`maxBudgetUsd` (with an alpha `taskBudget`). Resumed sessions now carry prior spend into their totals (v2.1.277+) and `-p`/SDK resumes do NOT restore permission mode.

### Cited Findings
- Session options on `query()`: `resume: string` (session ID), `forkSession: boolean` (default `false`; with `resume`, fork to a new session ID), `continue: boolean` (default `false`; most recent conversation in cwd), `sessionId: string` (specific UUID), `persistSession: boolean` (default `true`; `false` = no disk persistence and no resume), `resumeSessionAt: string` (resume at a message UUID), `resumeDropsTurn: string` (with `resumeSessionAt`, requires v2.1.223+), `sessionStore: SessionStore`, `sessionStoreFlush: 'batched' | 'eager'` (alpha, default `'batched'`), `loadTimeoutMs: number` (alpha, default `60000`), `title: string` (display title; a resumed session's title wins), `enableFileCheckpointing: boolean` (default `false`, enables `rewindFiles()`), `projectConfigRoot: string` (trusted checkout that `cwd` is a worktree of; v2.1.275+) — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `forkSession` "creates a new session that starts with a copy of the original's history. The original stays unchanged"; the fork's ID arrives on the `system`/`init` message and on the `result` message. Fork branches the conversation, not the filesystem (use file checkpointing for that) — [Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions)
- The experimental V2 `createSession()` API "was removed in TypeScript Agent SDK 0.3.142" — [Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions)
- Prewarm: `startup(params?: { options?: Options; initializeTimeoutMs?: number }): Promise<WarmQuery>` — "Spawns the CLI and completes the initialize handshake early. Call `.query(prompt)` on the returned `WarmQuery` later"; `initializeTimeoutMs` defaults to `60000` — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Standalone session functions: `listSessions(options?: { dir?, limit?, includeWorktrees? (default true) }): Promise<SDKSessionInfo[]>` (sorted by `lastModified` newest first); `getSessionInfo(sessionId, { dir? })`; `getSessionMessages(sessionId, { dir?, limit?, offset?, includeSystemMessages? (default false) }): Promise<SessionMessage[]>` where `SessionMessage` has `type`, `uuid`, `session_id`, `message`, `parent_tool_use_id`, `parent_agent_id` (v2.1.202+); `renameSession(sessionId, title, options?)` ("appends a custom-title entry… most recent title wins"); `tagSession(sessionId, tag: string | null, options?)` ("Pass `null` to clear the tag. The most recent tag wins"); `forkSession(sessionId, { dir?, upToMessageId?, title? }): Promise<{ sessionId }>` — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `deleteSession()`, `listSubagents()`, `getSubagentMessages()` are listed as store-aware functions ("Supported on" list) — [Persist sessions to external storage](https://code.claude.com/docs/en/agent-sdk/session-storage)
- `SessionStore` interface: required `append(key: SessionKey, entries: SessionStoreEntry[])` and `load(key): Promise<SessionStoreEntry[] | null>`; optional `listSessions`, `listSessionSummaries`, `delete`, `listSubkeys`. `SessionKey = { projectKey; sessionId; subpath? }` where `projectKey` "is a stable, filesystem-safe encoding of the working directory" so you must resume "from a working directory matching the original run's". Dual-write: local JSONL first, then mirrored; a run resumed from the store deletes its local copy at run end. `persistSession: false` and `enableFileCheckpointing` conflict with a store (SDK throws at startup). Mirror writes are best-effort (3 attempts), failures emit `{ type: "system", subtype: "mirror_error" }`; deduplicate by `entry.uuid`. `InMemorySessionStore` ships for tests — [Persist sessions to external storage](https://code.claude.com/docs/en/agent-sdk/session-storage)
- Transcript location: `~/.claude/projects/<encoded-cwd>/*.jsonl` (or `$CLAUDE_CONFIG_DIR/projects/`), encoded by replacing non-alphanumerics with `-`; names over 200 chars are truncated + hashed; `CLAUDE_CODE_PROJECT_DIR_NAME` (with `CLAUDE_CONFIG_DIR`) pins the directory name (SDK v0.3.234+). Cross-directory resume lookup requires v2.1.223+; "Before v2.1.223, the lookup was scoped to the current project directory and its git worktrees" — [Work with sessions](https://code.claude.com/docs/en/agent-sdk/sessions); [Manage sessions](https://code.claude.com/docs/en/sessions)
- The transcript "entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release" — [Manage sessions](https://code.claude.com/docs/en/sessions)
- `-p`/SDK sessions "are left out of the session picker and out of `claude --continue`" (resumable by ID); `claude -p --continue` does include them — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Permission mode on resume: non-interactive `claude -p --resume` "starts the run in the permission mode a new `claude -p` run would start in"; a `bypassPermissions` session resumed in a terminal also drops to the default mode. Not restored on resume: `--mcp-config`, `--settings`, `--plugin-dir`, `--fallback-model`, `--add-dir`; background Bash/monitor tasks are not restarted; unexpired `CronCreate` tasks are — [Manage sessions](https://code.claude.com/docs/en/sessions)
- Session state events: `CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS=1` adds `SDKSessionStateChangedMessage { type: "system"; subtype: "session_state_changed"; state: "idle" | "running" | "requires_action" }`; "Claude Code can report the same state more than once"; "A turn's `idle` message and its `result` message can arrive in either order"; `CLAUDE_CODE_BG_TASKS_REPORT_RUNNING=0` makes idle report even while background work runs (default/opt-out requires v2.1.269+) — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript); [Environment variables](https://code.claude.com/docs/en/env-vars)
- `SDKResultMessage` subtypes: `success`, `error_max_turns`, `error_during_execution`, `error_max_budget_usd`, `error_max_structured_output_retries`. Fields on both arms: `duration_ms`, `duration_api_ms`, `is_error`, `num_turns`, `stop_reason` (`string | null`), `total_cost_usd`, `usage`, `modelUsage`, `permission_denials`, `terminal_reason`, `result_index`, `fast_mode_state`, `fast_mode_disabled_reason`, `origin`. Success-only: `result`, `structured_output?`, `ttft_ms`, `ttft_stream_ms`, `time_to_request_ms`, `deferred_tool_use`. Error-only: `errors: string[]`, `startup_failure_reason?`. `terminal_reason` values include `"completed"`, `"max_turns"`, `"tool_deferred"`, `"aborted_streaming"`, `"aborted_tools"`, `"budget_exhausted"`, `"api_error"` — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `usage` "covers only the main loop. Prefer `modelUsage` for accounting. `modelUsage` covers all model calls in the `query()` call, including subagents"; `modelUsage[model]` carries `costUSD`, `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`, `thinkingTokens` (v0.3.257+), `costBasis: "list" | "managed" | "unknown"` (v2.1.246+). `total_cost_usd` is a client-side estimate from a bundled price table, "not authoritative billing data" — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Per-step `output_tokens` on assistant messages "is a placeholder"; read output tokens from the result. Parallel tool calls share one message `id`, so dedupe by ID — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Resumed sessions: "Claude Code saves the session's totals to its transcript when the process exits normally and restores them when a later call resumes or forks the session. Each result already includes the session's earlier spend… Before v2.1.277, a session that you resumed through the SDK or `claude -p` started its totals at zero" — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- A session crash emits a final `error_during_execution` whose cost fields "may be zeroed" and `stop_reason` is `null`, then the process exits — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- `SDKRateLimitEvent { type: "rate_limit_event"; rate_limit_info: { status: "allowed" | "allowed_warning" | "rejected"; resetsAt?; utilization?; errorCode?: "credits_required"; canUserPurchaseCredits?; hasChargeableSavedPaymentMethod? } }`; `credits_required` fields require v2.1.181+ — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `system/api_retry` events carry `attempt`, `max_retries`, `retry_delay_ms`, `error_status`, `no_response` (v2.1.261+), and `error` in `authentication_failed | oauth_org_not_allowed | account_on_hold | billing_error | rate_limit | overloaded | invalid_request | model_not_found | server_error | max_output_tokens | cloud_credential_error | unknown` — [Run Claude Code programmatically](https://code.claude.com/docs/en/headless)
- Limits: `maxTurns` (no default; counts each turn with tool calls plus one for the final text-only turn), `maxBudgetUsd` (no default; "Client-side cost cap; leave headroom" — spend can pass the cap by one response plus running subagents; cap enforcement incl. subagents requires v2.1.217+; with streaming input a `/clear` restarts the budget and restored session spend does not count), `taskBudget: { total: number }` (alpha, "Token budget shown to the model") — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript); [How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- A single-shot `query()` "throws after yielding an error result"; "A streaming input session stays alive, and you can keep sending messages, except after a session crash" — [How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- `interrupt()` is streaming-input only and "Resolves with a receipt (`still_queued`, `cancelled`) on CLI v2.1.205+"; init-message `capabilities` strings include `interrupt_receipt_v1`, `interrupt_cancel_queued_v1` (v2.1.219+), `sdk_mcp_manifests`, `sdk_mcp_tools_list_changed`, `mcp_read_resource_v1` — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `Query` object methods not yet in Neo's inventory: `rewindFiles(userMessageId, { dryRun? })`, `setModel()`, `applyFlagSettings()` (streaming only; `null` clears a key), `updateSettings(source, settings)`, `initializationResult()`, `reinitialize()` (v2.1.195+), `supportedCommands()/supportedModels()/supportedAgents()`, `mcpServerStatus()`, `getContextUsage({ detail?: 'full' | 'summary' })` (`detail` v0.3.257+), `readFile(path, { maxBytes?, encoding? })` (1 MB default, 10 MB ceiling), `reloadPlugins({ holdOnCacheImpact?, addPlugins? })`, `reloadSkills()` (v0.3.163+), `seedReadState(path, mtime)`, `accountInfo()`, `reconnectMcpServer(name)`, `toggleMcpServer(name, enabled)`, `setMcpServers(servers)`, `setMcpPermissionModeOverride(name, 'default' | 'auto' | null)`, `streamInput(stream)`, `stopTask(taskId)`, `backgroundTasks(toolUseId?)` (v0.2.139+), `close()` — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Transcript size control for long headless sessions: `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC=1` — "After each compaction, once the file is larger than 5 MB, Claude Code removes the history from before that compaction" (v2.1.287+; must be set in the process env, not a settings `env` block). `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` auto-resumes a session that ended mid-turn "Used in SDK mode so the model continues without requiring the SDK to re-send the prompt" — [Environment variables](https://code.claude.com/docs/en/env-vars)
- Changelog items on resume: 2.1.311 "Fixed `-p` and SDK sessions saving transcript messages out of order"; 2.1.304 "Resuming a large compacted session is faster in SDK and headless mode"; 2.1.300 fixed headless/SDK resume losing or re-adding compaction-era messages; 2.1.299 fixed "an approved tool call running twice on resume (a 2.1.296 regression)"; 2.1.314 `claude -p` "now exits 1 with the error when startup fails, instead of exiting 0 with no output" — [Changelog](https://code.claude.com/docs/en/changelog)

### Inferences
- Neo's ledger should key accounting off `modelUsage`/`total_cost_usd`, not `usage`, and must not sum results across resumed calls (double counts after v2.1.277).
- `startup()` + `WarmQuery` is the documented prewarm path for an engine that wants the subprocess handshake done before the order arrives.
- `tagSession`/`renameSession` give Neo a way to label worker sessions (e.g. project/order id) without writing to the transcript format directly.
- `CLAUDE_CODE_TRANSCRIPT_LOCAL_GC` and `CLAUDE_CODE_RESUME_INTERRUPTED_TURN` are directly relevant to a long-running daemon but are both newer than Neo's pinned 0.3.291 bundle (GC requires v2.1.287+ so it is available; `RESUME_INTERRUPTED_TURN` fixes landed in 2.1.296/2.1.299).

### Gaps
- The docs do not state the SDK's own exact-to-CLI version mapping for 0.3.291; the "SDK vX tracks Claude Code vX" rule is the only documented mapping.
- `SDKSessionInfo` field list was not visible in the fetched chunks (only its existence and `lastModified` sort order).
- `taskBudget` semantics beyond "token budget shown to the model" are not documented (alpha).

## 2. Context: compaction controls, context reporting, memory/auto-memory, CLAUDE.md loading, 1M context, prompt caching

### Takeaway
Compaction is automatic with `compact_boundary` events, `PreCompact`/`PostCompact` hooks, `/compact` dispatch, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, per-subagent `autoCompactWindow` (v0.3.296+), idle compaction (v2.1.290+), and `getContextUsage()`. Auto memory lives at `~/.claude/projects/<project>/memory/` and loads regardless of `settingSources` unless disabled; CLAUDE.md loading is fully governed by `settingSources`. 1M context is on by default for Opus/Sonnet 5.5 or via `[1m]`; prompt cache TTL is 1h on subscription main-conversation turns and 5m elsewhere, controllable per bucket.

### Cited Findings
- Automatic compaction emits `SDKCompactBoundaryMessage { type: "system"; subtype: "compact_boundary"; compact_metadata: { trigger: "manual" | "auto"; pre_tokens: number } }`; customize via CLAUDE.md summarization instructions, a `PreCompact` hook, or sending `/compact` as a prompt — [How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop); [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- `CLAUDE_CODE_AUTO_COMPACT_WINDOW`: `100000` to `1000000` tokens; `k`/`M` suffixes require v2.1.304+ ("`200k` no longer silently sets a 100K window"). `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` (default `200000`, v2.1.290+); idle compaction is disabled with `"idleCompaction": false`. `DISABLE_COMPACT=1` disables all compaction. `CLAUDE_CODE_MAX_CONTEXT_TOKENS` overrides the assumed context window — [Environment variables](https://code.claude.com/docs/en/env-vars); [Changelog](https://code.claude.com/docs/en/changelog)
- Idle compaction "summarizes a 200K+ token conversation left idle, so the next message can use the summary once the prompt cache expires" (2.1.314); 2.1.299 notes it is "terminal only" and runs at about 54 minutes idle — [Changelog](https://code.claude.com/docs/en/changelog)
- Per-agent `autoCompactWindow: number` on `AgentDefinition` (100000–1000000; TypeScript SDK v0.3.296+) — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents)
- Context reporting: `getContextUsage({ detail? })` on the `Query` object (`'full'` default uses token-counting requests; `detail` needs v0.3.257+); sending `/context` as a prompt returns an assistant message with a `context_usage` payload (`SDKContextUsage`, v0.3.232+); `SDKStatusMessage { subtype: "status"; status: "compacting" | null; permissionMode? }` signals compaction in progress — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Auto memory: loaded "into the system prompt at session start" from `~/.claude/projects/<project>/memory/`; "The agent writes new memories there with the standard `Write` and `Edit` tools rather than a dedicated memory tool, so those tools must be enabled for the agent to save memories"; disable with `autoMemoryEnabled: false` or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` in `env`; it is read "regardless of `settingSources`". Multi-tenant advice: "run each tenant in its own filesystem and set `settingSources: []` plus `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`" — [Use Claude Code features in the SDK](https://code.claude.com/docs/en/agent-sdk/claude-code-features)
- Auto memory is "Per repository, shared across worktrees" and loaded "Every session (first 200 lines or 25KB)"; subagents "can also maintain their own auto memory" (`memory: 'user' | 'project' | 'local'` on `AgentDefinition`) — [How Claude remembers your project](https://code.claude.com/docs/en/memory); [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents)
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=0` "force[s] auto memory on, even when `--bare` mode or `autoMemoryEnabled: false` would disable it" — [Environment variables](https://code.claude.com/docs/en/env-vars)
- The system prompt "embeds your auto memory paths, and the conversation opens with an announcement of the working directory", so caches are effectively scoped per machine+directory; for SDK fleets see "improve prompt caching across users and machines" (move the auto memory location out of the system prompt) — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- CLAUDE.md load rules by `settingSources`: `"project"` loads `<cwd>/CLAUDE.md` or `<cwd>/.claude/CLAUDE.md`, `.claude/rules/*.md` in cwd and every parent, parent-directory `CLAUDE.md` at session start, child-directory `CLAUDE.md` on demand; `"local"` loads `CLAUDE.local.md` (cwd + parents) and `.claude/settings.local.json`; `"user"` loads `~/.claude/CLAUDE.md` and `~/.claude/rules/*.md`. Omitting `settingSources` equals `["user","project","local"]`; `[]` disables all three. Managed policy settings, `~/.claude.json`, auto memory, claude.ai MCP connectors, and `sandbox.credentials` deny/mask entries load regardless — [Use Claude Code features in the SDK](https://code.claude.com/docs/en/agent-sdk/claude-code-features)
- CLAUDE.md files "in the directory hierarchy above the working directory are loaded at launch. Files in subdirectories load on demand" (when Claude reads/writes/edits a file there); `@path` imports expand; `claudeMdExcludes` skips files by glob; `AGENTS.md` is read when no `CLAUDE.md`/`CLAUDE.local.md` exists in cwd or above (v2.1.277+; configurable via `cc-plugin-agents-md@builtin` `pluginConfigs` with values `claude-md-or-agents-md` (default), `claude-md-and-agents-md`, `managed-only`) — [How Claude remembers your project](https://code.claude.com/docs/en/memory)
- `AgentDefinition.omitClaudeMd: boolean` leaves user/project/local CLAUDE.md out of a subagent's context (v0.3.271+) — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents)
- Editing root/user CLAUDE.md mid-session neither invalidates the cache nor applies; "The new content loads on the next `/clear`, `/compact`, or restart" — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- 1M context: `SdkBeta = "context-1m-2025-08-07"` is retired for Sonnet 4.5/4; "For a 1M context window, use a model that runs with 1M by default (for example `claude-sonnet-5-5` or `claude-opus-5-5`), or append `[1m]` to a model ID"; `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` holds 1M-default models to 200K — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript); [Environment variables](https://code.claude.com/docs/en/env-vars)
- 2.1.311 fixed "standard-context sessions stopping with 'Usage credits required for 1M context' when a request went over 200K. Claude Code now compacts and continues"; 2.1.316 `/model <id>` warns when auto-compact will assume a 200K window for an unrecognized model — [Changelog](https://code.claude.com/docs/en/changelog)
- Prompt caching TTL buckets: "Main conversation: your interactive turns, non-interactive `-p` runs, and Agent SDK turns" get one hour on a Claude subscription within plan usage, five minutes on usage credits/API key; "Everything else" (subagents, workflows, teammates, forks, compaction, session titles) gets five minutes. Controls: `promptCacheTtl`/`CLAUDE_CODE_PROMPT_CACHE_TTL` and `subagentPromptCacheTtl`/`CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (`5m`|`1h`, v2.1.242+), `ENABLE_PROMPT_CACHING_1H=1`, `FORCE_PROMPT_CACHING_5M=1`. Verify with `usage.cache_creation.ephemeral_1h_input_tokens` vs `ephemeral_5m_input_tokens` — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Cache invalidators: model switch, effort change (not on Opus 5.5/Sonnet 5.5/Haiku 5.5/Fable 5.1 with API key or subscription), fast mode toggle, MCP server connect/remove when tool search is off, plugin MCP changes, bare-name tool deny, compaction, many images, Claude Code upgrade. Cache keepers: permission mode changes, output style, skills, `/rewind`, subagent spawn — [How Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)
- `claude -p` "Pro/Max users get a warning when resuming an inactive conversation would use a noticeable share of the 5-hour limit" (2.1.304) — [Changelog](https://code.claude.com/docs/en/changelog)

### Inferences
- Neo's "context sweet spot" logic can read `getContextUsage({ detail: 'summary' })` cheaply instead of estimating; `pre_tokens` on `compact_boundary` gives the measured size at each compaction.
- Because auto memory loads irrespective of `settingSources`, Neo's per-project worker already carries `~/.claude/projects/<encoded-folder>/memory/` unless disabled; this overlaps with Neo's own memory Phase 2 and should be an explicit decision.
- The 5-minute subagent TTL (even on subscription) means dispatch patterns that fan out subagents with gaps >5 min pay re-cache costs; `subagentPromptCacheTtl: "1h"` is the knob.

### Gaps
- The exact on-disk layout of auto memory beyond `MEMORY.md`-style "first 200 lines or 25KB" was not captured from the memory page excerpt.
- No documented API for reading compaction summaries from the SDK stream other than the `PostCompact` hook's `compact_summary`.

## 3. Subagents and teams: `agents`, agent teams headless, background tasks, re-invocation

### Takeaway
Programmatic `agents` now support `background`, `maxTurns` (partial marking), `autoCompactWindow`, `omitClaudeMd`, `memory`, `skills` preload, `mcpServers`, `effort`, and resumable subagents (`agentId` + `resume`). Agent teams exist only in interactive Claude Code: "In non-interactive mode with the `-p` flag, including Agent SDK sessions, Claude doesn't spawn teammates". Background Bash/subagent completion is delivered as `task_notification` system messages and starts a new turn in the same session; one-shot `-p`/SDK runs wait up to 10 minutes idle for background work.

### Cited Findings
- `AgentDefinition` fields: `description` (req), `prompt` (req), `tools`, `disallowedTools` (accepts `mcp__server`, `mcp__server__*`, `mcp__*`), `model` (alias incl. `'inherit'` or full ID), `skills` (first 32 preloaded), `memory: 'user' | 'project' | 'local'`, `mcpServers: (string | object)[]`, `initialPrompt` (main-thread agent only), `maxTurns` (partial marking v2.1.246+), `autoCompactWindow` (v0.3.296+), `background: boolean`, `omitClaudeMd` (v0.3.271+), `effort`, `permissionMode` — [Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents)
- Query-level: `agent: string` (main-thread agent), `agents: Record<string, AgentDefinition>`, `agentProgressSummaries: boolean` (default `false`; fills `summary` on `task_progress`), `forwardSubagentText: boolean` (default `false`; forward subagent text/thinking with `parent_tool_use_id`) — [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Foreground vs background: "By default, a subagent your main agent spawns runs in the background. ### Inferences
- Neo cannot use agent teams headlessly; the documented headless equivalents are programmatic subagents (with `background: true`), the `Workflow` tool for large fan-outs, and multiple engine-spawned sessions coordinated by Neo itself.

- Whether a streaming-input SDK session is "woken" for a `task_notification` while idle (vs only at next turn) is implied but not stated verbatim.
- Cross-session messaging page content was not fetched.

## 4. Permissions: modes, canUseTool vs hooks ordering, denials, settings rules, sandbox, dangerous flags, hooks catalogue

### Takeaway
Evaluation order is fixed: hooks → deny rules → ask rules → permission mode → allow rules → `canUseTool`. `PermissionMode` is `default | acceptEdits | bypassPermissions | plan | dontAsk | auto`; `permissionPrompts: 'none'` (v2.1.259+) makes unattended runs deny-not-wait; `canUseTool` is skipped for anything auto-approved earlier (warning `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`). The TS SDK supports 33 hook events including `SessionStart/End`, `Stop`, `PermissionRequest`, `TeammateIdle`, `TaskCompleted`, `PreCompact/PostCompact`, `PreModelSwitch`, and a `PreToolUse` `defer` decision that ends the turn so a process can exit and resume later.

### Cited Findings
- Evaluation order: "1. Hooks … 2. Deny rules … 3. Ask rules … 4. Permission mode … 5. Allow rules … 6. canUseTool callback"; a hook `allow` "doesn't skip the deny and ask rules"; deny rules apply "even in `bypassPermissions` mode and even when a hook returned `allow`"; in `dontAsk` step 6 is skipped and the tool denied — [Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions)
- `PermissionMode = "default" | "acceptEdits" | "bypassPermissions" | "plan" | "dontAsk" | "auto"`; `bypassPermissions` requires `allowDangerouslySkipPermissions: true` and "Claude Code refuses to start in this mode as root or under `sudo` outside a recognized sandbox"; `auto` = model classifier reviews shell/network actions; switching to a model auto mode doesn't support drops the session to `default` with an `SDKStatusMessage` (v2.1.299+) — [Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions); [TypeScript reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Default mode: "With Claude Code v2.1.302 or later, your app starts in `default` mode unless you set a permission mode or it gets one from `permissions.defaultMode`"; in `default`, calls needing approval are denied unless approved by rule, hook, `canUseTool`, or permission prompt tool — [Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions)
- `canUseTool` shadowing warning: the SDK "emits a Node.js process warning once… code is `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED`" for `bypassPermissions` or bare-name `allowedTools` entries — [Configure permissions](https://code.claude.com/docs/en/agent-sdk/permissions)

### Inferences
- Neo's governor design (PreToolUse `ask` → `canUseTool`) is consistent with the documented precedence; `permissionPrompts: 'none'` plus a `PermissionRequest` hook is the documented pattern for autonomous paths that must auto-deny instead of waiting.
- `defer` is the documented way to park an approval across a daemon restart (the pending call lives in the transcript) — relevant to Neo's approval-timeout design (ADR-0012) if it ever wants to survive a reload without denying.
- `permissions.blockWritesOutsideWorkingDirectories` (2.1.314) is a code-level fence that could replace part of Neo's path-fence logic for customer work once upgraded.

### Gaps
- `PermissionRequest` hook vs `canUseTool` ordering for the SDK callback form is only described by the settings-file flow; no explicit sentence orders the two for TS callbacks.
- `SessionEnd` `reason` values were only partially captured (`clear`, `resume`, `logout`, `prompt_input_exit`, `other`; `bypass_permissions_disabled` removed in v2.1.234).

## 6. Scheduling and remote: scheduled tasks/routines, cloud sessions API, GitHub Actions, channels, overlap with a self-hosted engine

### Takeaway
Claude Code now ships three schedulers (session-scoped `/loop`+`CronCreate`, Desktop tasks, cloud "scheduled tasks" formerly routines with schedule/API/GitHub triggers), push-style channels (Telegram/Discord/iMessage plugins, research preview, interactive sessions only), cloud sessions with a `--cloud` CLI and `claude -p --cloud <id>` message queueing, and the `claude-code-action` GitHub Action which accepts a subscription OAuth token. - Cloud scheduled tasks (research preview; "formerly routines"): triggers = schedule (≥ hourly; cron in UTC or `CRON_TZ=`), API (`POST https://api.anthropic.com/v1/claude_code/routines/<trig_id>/fire` with `Authorization: Bearer`, optional `text` body, beta header `experimental-cc-routine-2026-04-01`, returns `claude_code_session_id` and `claude_code_session_url`), GitHub events (per-task/per-account hourly caps). - Comparison table: Cloud (no machine, no local files, auto mode, 1 h min), Desktop (machine on, local files, 1 min), `/loop` (open session, inherits MCP/permissions, 1 min) — [Run prompts on a schedule](https://code.claude.com/docs/en/scheduled-tasks)

## 8. Codex SDK (`@openai/codex-sdk`) thread model, sandbox, approvals, events, resume, gaps vs Claude

### Takeaway
The Codex SDK is a thin wrapper that spawns `codex exec --experimental-json` per turn, passing `ThreadOptions` as CLI flags/`--config` overrides; threads resume by `thread_id` (`resume <id>`), events are a flat JSONL union (`thread.started`, `turn.started/completed/failed`, `item.started/updated/completed`, `error`) with eight item types, and there is no per-tool permission callback, no hooks API, no session-state events and no cost field (usage only). Policy is set up front via `approvalPolicy` (`never | on-request | on-failure | untrusted`) and `sandboxMode` (`read-only | workspace-write | danger-full-access`).

### Cited Findings
- Package: `npm install @openai/codex-sdk`, Node 18+; "Wraps the `codex` CLI from `@openai/codex`, spawned as a subprocess that exchanges JSONL events over stdin/stdout"; latest `0.166.0` on npm (2026-11-01) — [Codex TypeScript SDK README](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/README.md); npm registry (`npm view @openai/codex-sdk`)
- `Codex` constructor options documented: `env`, `config` (flattened to `--config key=value` as TOML literals), `configOverrides` (raw TOML strings), `baseUrl` (`--config openai_base_url=…`); precedence `config` → `configOverrides` → SDK-managed settings — [Codex TypeScript SDK README](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/README.md)
- `ThreadOptions = { model?; threadSource?; sandboxMode?: "read-only" | "workspace-write" | "danger-full-access"; workingDirectory?; skipGitRepoCheck?; modelReasoningEffort?: "minimal" | "low" | "medium" | "high" | "xhigh" | "max" | "ultra" | "persistent"; networkAccessEnabled?; webSearchMode?: "disabled" | "cached" | "live"; webSearchEnabled?; approvalPolicy?: "never" | "on-request" | "on-failure" | "untrusted"; additionalDirectories? }` — [threadOptions.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/threadOptions.ts)
- `Thread`: `id: string | null` ("Populated after the first turn starts"), `run(input, turnOptions?): Promise<Turn { items, finalResponse, usage }>`, `runStreamed(input, turnOptions?): Promise<{ events: AsyncGenerator<ThreadEvent> }>`; `Input = string | ({ type: "text"; text } | { type: "local_image"; path })[]`; `TurnOptions`: `outputSchema` (written to a temp file → `--output-schema`), `signal`, `cyberAccessProgram`; `run()` throws `new Error(turnFailure.message)` on `turn.failed`; resume via `threadId` on each call — [thread.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/thread.ts)
- CLI mapping in `CodexExec.run`: base `["exec", "--experimental-json"]`; `--model`, `--sandbox <mode>`, `--cd <dir>`, `--add-dir`, `--skip-git-repo-check`, `--output-schema <file>`, `--image`, `resume <threadId>`, `--thread-source` (only without a `threadId`); `--config` entries for `model_reasoning_effort="…"`, `sandbox_workspace_write.network_access=…`, `web_search="…"`, `approval_policy="…"`; abort `signal` passed to `spawn` and `child.kill()` in `finally`; env `CODEX_API_KEY` (when `apiKey` given) and `CODEX_INTERNAL_ORIGINATOR_OVERRIDE="codex_sdk_ts"` — [exec.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/exec.ts)
- Events: `thread.started { thread_id }`, `turn.started`, `turn.completed { usage }`, `turn.failed { error: ThreadError { message } }`, `item.started|updated|completed { item }`, `error { message }`; `Usage = { input_tokens, cached_input_tokens, cache_write_input_tokens, output_tokens, reasoning_output_tokens }` — [events.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/events.ts)
- Items: `agent_message { text }`, `reasoning { text }`, `command_execution { command, aggregated_output, exit_code?, status: in_progress|completed|failed }`, `file_change { changes[{ path, kind: add|delete|update }], status: completed|failed }`, `mcp_tool_call { server, tool, arguments, result?, error?, status }`, `web_search { query }`, `todo_list { items[{ text, completed }] }`, `error { message }` — [items.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/items.ts)
- Threads persist in `~/.codex/sessions`; `codex.resumeThread(threadId)` reconstructs a thread; the working directory must be a git repo unless `skipGitRepoCheck` — [Codex TypeScript SDK README](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/README.md)
- Codex config supports `allow_managed_hooks_only` in `requirements.toml` ("user, project, and session hook configs are ignored. Managed hooks from requirements and managed config layers still apply"), implying a lifecycle-hooks config layer exists in the CLI, but the SDK exposes no hook callback — [codex docs/config.md](https://raw.githubusercontent.com/openai/codex/main/docs/config.md)
- Not in the SDK source: no `canUseTool`/approval callback, no hook registration, no permission-denial list, no cost-in-USD field, no session-state events; `approvalPolicy` is the only control and it is forwarded as config at spawn time — [thread.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/thread.ts); [exec.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/exec.ts)
- Neo's CLAUDE.md already notes "Codex uses sandbox/approval policy, not Claude's `canUseTool` hook" (project file `/home/user/neo/CLAUDE.md`).

### Inferences
- A Neo governor for Codex must be external: pick `approvalPolicy: "never"` + a restrictive `sandboxMode` (`read-only`/`workspace-write`) and `networkAccessEnabled: false`, then audit `command_execution`/`file_change` items after the fact; there is no pre-execution veto point like `PreToolUse`.
- Because each turn is a fresh `codex exec` subprocess, "interrupt" is only `signal` abort (kills the process); there is no streaming-input, mid-turn steer, or permission-mode switch.

### Gaps
- `developers.openai.com` (config reference, non-interactive mode, sandbox & approvals pages) is unreachable from this session, so the semantics of `on-failure`/`on-request` in non-interactive `exec` (whether it auto-denies or fails) and `workspace-write` writable roots are undocumented here; `docs/exec.md` and `docs/sandbox.md` in the repo are redirect stubs.
- Codex SDK changelog/known issues were not researched.

## 9. Known issues and 2026 changelog items affecting long-running headless use

### Takeaway
Two recurring field problems are documented in GitHub issues: wedged API streams with no client-side inactivity watchdog (issues #53584, closed as duplicate of #33949 in April 2026; #87692, closed "not planned" by the stale bot in October 2026), and headless runs dying terminally on retryable 429/5xx. Anthropic's 2.1.29x–2.1.31x releases added retry knobs (`CLAUDE_CODE_RETRY_WATCHDOG*`, `CLAUDE_CODE_OVERLOADED_RETRY_*`), a 300 s no-data wait for gateways, non-retryable-error handling, and multiple resume/transcript-ordering fixes.

### Cited Findings
- Issue #53584 (opened and closed 2026-04-26, CC 2.1.119, also reproduced with Python SDK 0.1.68): `claude --print --output-format=stream-json --input-format=stream-json --resume <id>` "sometimes hangs after it starts receiving a streamed response… No error is logged"; no maintainer reply; closed as duplicate of #33949; reporter's watchdog kills after 10 min without a significant event, hard 20-min cap per turn, respawn with `--resume` — [GitHub issue #53584](https://github.com/anthropics/claude-code/issues/53584)

- Cloud/headless: 2.1.311 "Background sessions that crash between turns are restarted when attached, pinned, or holding a scheduled task or wake-up"; 2.1.314 `permissions.blockWritesOutsideWorkingDirectories`, cloud scheduled tasks load claude.ai plugins, "Continue automatically at usage limit" capped at three continuations — [Changelog](https://code.claude.com/docs/en/changelog)
