## KQ1. How does each system isolate work and run many tasks in parallel?

### Takeaway
Every hosted product converged on one disposable VM/container per task, cloned from the repo (not the user's checkout), with a per-task branch and a draft PR as the output; local/CLI products isolate with git worktrees instead. Concurrency is a plan/quota knob (e.g. Replit 2/10 parallel agents by tier, Copilot ~5-7 observed then queueing, Devin "Managed Devins" each in their own VM) rather than an architectural limit.

### Cited Findings

**Claude Code (cloud sessions, scheduled tasks, Projects, agent teams, worktrees)**
- "each session runs in an isolated, Anthropic-managed VM"; "git credentials and signing keys stay outside the sandbox, and a proxy authenticates on the session's behalf with scoped credentials"; network access "is limited by default and can be disabled" — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- "The cloud VM clones your current directory's GitHub remote at your current branch, not your local checkout"; "each `--cloud` command creates its own cloud session that runs independently" — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Repos without a GitHub remote are bundled and uploaded: "The bundled repository must be under 100 MB"; uncommitted changes to `.env`, `*.tfvars`, `id_rsa`, `*.pem` are left out on macOS/Linux/WSL — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Environments: "Trusted network access: sessions reach package registries and other allowlisted domains, and nothing else"; the GitHub proxy "rejects branch deletions and pushes of anything other than a branch"; setup-script snapshot cached only if it "completes within roughly five minutes", cache expires "after roughly seven days"; "after a few minutes without activity, a session's VM pauses with its files saved" and may later be reclaimed — [Claude Code docs: cloud environments](https://code.claude.com/docs/en/cloud-environments.md)
- Scheduled tasks: "Each repository is cloned at the start of a run. Claude creates `claude/`-prefixed branches"; "Claude Code doesn't reuse sessions across events, so two PR updates produce two independent sessions"; "GitHub webhook events are subject to per-task and per-account hourly caps" — [Claude Code docs: scheduled tasks](https://code.claude.com/docs/en/routines)
- Projects: "Threads: the workers. Each is a separate session with its own context window that does one piece of work and reports back... A cloud thread works on its own branch and opens a pull request when the work calls for one" — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects.md)
- Five parallel modes are documented: subagents, agent view (`claude agents`), agent teams (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`), dynamic workflows, projects; "A session you dispatch from agent view moves into a worktree of its own before it edits files"; `/batch` splits one change "into 5 to 30 worktree-isolated subagents" — [Claude Code docs: agents](https://code.claude.com/docs/en/agents)
- Agent teams: "Agent teams don't isolate teammates in worktrees, so partition the work so each teammate owns a different set of files"; "Task claiming uses file locking"; mailboxes are JSON files at `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`; "No nested teams"; "Spawning teammates also requires an interactive session. In non-interactive mode with the `-p` flag, including Agent SDK sessions, Claude doesn't spawn teammates" — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams.md)
- Agent SDK: read-only tools run concurrently; "Tools that modify state (like `Edit`, `Write`, and `Bash`) run sequentially to avoid conflicts" — [Agent SDK: agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop.md)

**OpenAI Codex (cloud + CLI + SDK)**
- Codex cloud "Runs in isolated OpenAI-managed containers, preventing access to your host system"; "Secrets configured for cloud environments are available only during setup and are removed before the agent phase starts" — [OpenAI Codex docs (agent approvals & security)](https://developers.openai.com/codex/agent-approvals-security.md)
- Two-phase model: container created, repo checked out, setup script runs (optional maintenance script when a cached container resumes), then "Internet access is applied afterward"; agent-phase internet "is blocked ... by default" and can be set to On or a domain allowlist with allowed HTTP methods — [Codex cloud environments (legacy page)](https://developers.openai.com/codex/cloud/environments); [Codex agent internet](https://developers.openai.com/codex/cloud/agent-internet)
- A 12-hour container cache is reported (secondary, unverified) — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/05/31/codex-cloud-environments-setup-scripts-caching-secrets-codex-universal/)
- Local CLI isolates with OS primitives, "Seatbelt and bubblewrap + seccomp, not containers" (secondary) — [blakecrosley.com](https://blakecrosley.com/guides/codex)
- `codex cloud exec --attempts` runs best-of-N "of up to four", default 1, labelled experimental (secondary) — [agent37](https://www.agent37.com/blog/codex-cloud)
- App "Automations" run "in a background worktree and surface results for human review" (secondary) — [codex.danielvaughan.com](https://codex.danielvaughan.com/2026/03/27/codex-cli-automations-scheduled-tasks/)
- Self-hosted option: Cloudflare Sandboxes run each Codex session in its own Linux container — [Cloudflare docs](https://developers.cloudflare.com/sandbox/coding-agents/openai-agents-api/)

**Cursor cloud agents**
- "Cursor provisions an isolated VM for that agent and clones the authorized repository into it"; "the runtime workspace is recycled automatically after the run goes idle, and VM snapshots are kept for a rolling 90 days of inactivity" — [Cursor docs: cloud-agent security](https://prod.cursor.com/docs/cloud-agent/security)
- Launch surfaces: desktop, web, iOS, Slack, Linear, GitHub/Bitbucket `@cursor` comment, API; follow-ups "queue behind the current run, or interrupt it on request" — [Cursor docs: BDK cloud agents](https://cursor.com/docs/bdk/guides/cloud-agents)
- Self-hosted pool on Vercel Sandbox: "maximum session duration is 45 minutes" — [Vercel docs](https://vercel.com/docs/sandbox/ecosystem/cursor)
- Cursor's own scale experiment: "Hundreds of workers run concurrently, pushing to the same branch with minimal conflicts" (workers resolve conflicts themselves) — [Cursor blog: Scaling long-running autonomous coding](https://cursor.com/blog/scaling-agents)

**GitHub Copilot coding agent**
- "spins up a secure and fully customizable development environment powered by GitHub Actions"; pushes commits to a draft PR — [GitHub Blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)
- Firewall: "Internet access is restricted by a firewall, but default rules allow access to a number of hosts" — [Microsoft Learn](https://learn.microsoft.com/en-us/training/modules/github-copilot-code-agent/4-customize-extend-validate-copilot-code-agent)
- Concurrency: "first 5-7 sessions start quickly and later ones queue for 5-17 minutes"; "59-minute per-session execution timeout" is the only documented hard limit (community discussion) — [GitHub Community #199770](https://github.com/orgs/community/discussions/199770)

**Google Jules**
- "Jules runs in a temporary virtual machine for each task. Users can customize the environment with setup scripts. A snapshot of that customized environment is then created"; VM size raised to 20 GB (2025-08-15); `jules remote new --parallel` starts multiple tasks from one prompt — [Jules changelog](https://jules.google/docs/changelog/)
- Default concurrency "up to 2 simultaneous tasks" (secondary, possibly outdated) — [digitalapplied](https://www.digitalapplied.com/blog/google-jules-gemini-async-coding-agent-guide)

**Devin (Cognition)**
- "Devin's Devbox is a fully-featured isolated Linux container" / per-session persistent VM (secondary) — [fast.io](https://fast.io/resources/cognition-devin-ai-architecture/)
- "Devin Manages Devins": "the main Devin session hand[s] work to a team of managed Devins running in parallel, each in its own isolated virtual machine. The coordinating session scopes the work, tracks progress, handles conflicts, and assembles the results"; GitHub.com only — [Devin release notes 2026](https://docs.devin.ai/release-notes/2026)
- Customer-run execution plane: "Devin's cloud is the control plane; your Tensorlake sandbox is the execution plane" — [Tensorlake](https://www.tensorlake.ai/blog/devin-outposts-on-tensorlake)
- Machine snapshots: "By default, all repositories share one machine snapshot. Advanced users can create additional machine snapshots" — [Devin docs release notes](https://docs.devin.ai/release-notes)

**Factory, OpenHands, Amp, Replit, Ona, Kilo**
- Factory cloud sandboxes are "Droid Computers"; droids run in terminal, desktop, browser, IDE, chat, CI job or "persistent remote computer" — [Factory docs CLI reference](https://docs.factory.ai/reference/cli-reference)
- OpenHands V1 SDK: "opt-in sandboxing" with `LocalWorkspace` swappable for `DockerWorkspace`; cloud workspace resumable by `sandbox_id` (issue) — [OpenHands SDK paper](https://arxiv.org/html/2511.03690v1); [software-agent-sdk #1602](https://github.com/OpenHands/software-agent-sdk/issues/1602)
- Replit Agent 4: "Independent requests can run in isolated copies of a project, appear on a shared Kanban board, and be reviewed before their changes are applied"; "two parallel agents on Core and ten on Pro" — [Tessl](https://tessl.io/blog/replits-agent-4-coordinates-multiple-ai-agents-to-build-apps-in-parallel)
- Ona: agents "work simultaneously on multiple tasks from a backlog, each operating inside its own workspace" (secondary) — [ai-deck](https://ai-deck.app/blog/ona/)
- Kilo Code background agents "run against a git worktree on a separate branch" (secondary) — [Faros](https://www.faros.ai/blog/best-ai-coding-agents-2026)
- Amp subagents "have their own context and can do multi-step work, but they are isolated: they cannot communicate" (secondary) — [with-agents.dev](https://with-agents.dev/posts/amp-factory-era-case-study/)

### Inferences
- The industry default for a self-hosted engine is: clone from remote (never the operator's working tree), one container/VM per task, credentials injected by a proxy rather than placed in the sandbox, setup-script snapshot cached with an expiry, branch-per-task with a product prefix (`claude/`), and a hard per-session wall clock.
- Worktrees are the local-machine substitute for VMs and are explicitly *not* used by Claude agent teams; Cursor shows that same-branch concurrency can work at scale only if workers own conflict resolution, which is a model-capability bet rather than an engine guarantee.

### Gaps
- No official Cursor maximum run duration was found (only the 45-minute Vercel self-hosted limit).
- Codex official concurrency and runtime limits were not found in reachable sources.
- Devin parallel-session caps conflict across secondary sources (10 vs. plan-based); the official docs page could not be fetched.

## KQ2. How does each verify its work before declaring done?

### Takeaway
Verification has split into three layers that the leaders now combine: (1) run the project's own tests/typecheck/lint inside the sandbox and show evidence; (2) a fresh-context second agent or second model that reviews the diff (Copilot self-review, Devin Review, Jules Planning Critic, Claude `/code-review` and ultrareview, Amp oracle, OpenHands critic); (3) browser/screenshot verification via Playwright MCP for UI work. Anthropic's and Cognition's own write-ups state that self-grading in the same context is unreliable, which is why the second-agent layer exists.

### Cited Findings
- Claude Code best practices: "Claude stops when the work looks done. If it has nothing to run that tells it whether the work actually *is* done, 'looks done' is all it has to go on"; options: prompt ("keep going until they pass"), `/goal` ("a condition that a separate model checks against the conversation after every turn"), a `Stop` hook that "sends Claude back to work if the script exits with code 2" (overridden after "eight stops in a row with no tool call between them"), `/code-review` in "a fresh subagent that never saw your conversation", `/verify` which "has Claude build and run the app and look at the result"; "ask Claude for *evidence*: the command it ran and its output, or the screenshot" — [Claude Code docs: best practices](https://code.claude.com/docs/en/best-practices)
- Ultrareview (`/code-review ultra`): "a fleet of reviewer agents in a cloud sandbox"; "every reported finding is independently reproduced and verified"; "5 to 15 minutes"; diff limit "up to 500 changed files and 8,000 changed lines by default"; `claude ultrareview --timeout` defaults to 45 minutes; cost "typically $5 to $25 in usage credits" after 3 free runs — [Claude Code docs: ultrareview](https://code.claude.com/docs/en/ultrareview.md)
- Anthropic harness post: "Out of the box, Claude was a poor QA agent. It identified real issues, then talked itself into approving the work"; agents "confidently praise the work"; fix was a standalone skeptical evaluator using "Playwright MCP to click through the running app" with hard per-criterion thresholds; generator and evaluator "negotiated a sprint contract before any code was written" (Sprint 3 had "27 testable criteria") — [Anthropic: Harness design for long-running apps](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- Cognition (April 2026): "A clean-context reviewer catches bugs the coder can't see. A frontier-level smart friend catches subtleties a weaker primary misses"; "Devin Review catches an average of 2 bugs per PR, of which roughly 58% are severe" (vendor statistic) — [Cognition: Multi-Agents, What's Actually Working](https://cognition.com/blog/multi-agents-working)
- Copilot coding agent "passes its own diff through Copilot code review before it opens a pull request, then gets feedback, iterates, and improves the patch" — [GitHub Blog: What's new with Copilot coding agent](https://github.blog/ai-and-ml/github-copilot/whats-new-with-github-copilot-coding-agent/); caveat from a 3-month user review: "if the agent picked a quick fix instead of addressing the root cause, the self-review will praise the quick fix" (secondary) — [Sean Kim](https://blog.imseankim.com/github-copilot-coding-agent-3-months-model-picker-self-review-cli-handoff-review/)
- Copilot Playwright MCP ships by default: "read, interact with, and take screenshots of web pages accessible inside the agent's environment (localhost/127.0.0.1)" — [Microsoft Learn](https://learn.microsoft.com/en-us/training/modules/github-copilot-code-agent/4-customize-extend-validate-copilot-code-agent)
- Jules: "Planning Critic for Auto-Approved Plans" (2026-01-26): a secondary agent "critiques and refines the proposed plan before Jules executes code", credited with "a 9.5% reduction in task failure rates"; original Critic Agent 2025-08-08; "Leveraging the improved multimodal capabilities of Gemini 3 Pro, Jules renders and verifies web app outcomes" — [Jules changelog](https://jules.google/docs/changelog/); [Planning Critic entry](https://jules.google/docs/changelog/2026-01-26-1/)
- Jules bot PR text example: "verifies that the unit tests for the 'dev' build variant are passing successfully"; one test-addition PR was reverted after "persistent, uninformative RuntimeExceptions" — [carlo-colombo/neurhome #175](https://github.com/carlo-colombo/neurhome/pull/175)
- OpenHands critic (experimental): "a critic score below a threshold triggers a retry", example `success_threshold` 0.7 and `max_iterations=3` retries; critic "hosted by the OpenHands LLM Provider and is currently free" — [OpenHands docs: critic](https://docs.openhands.dev/sdk/guides/critic)
- Amp: "ask it to 'use the oracle'" for deep reasoning; "The oracle uses GPT-5.4" (a second model) — [Amp manual: switch-from](https://ampcode.com/manual/switch-from)
- Codex cloud best-of-N `--attempts 1-4` ("let it take three swings and pick the best") (secondary) — [agent37](https://www.agent37.com/blog/codex-cloud)
- Replit Agent 4 coverage describes a detect/diagnose/fix/re-test loop with live in-browser preview (secondary/marketing) — [therundown](https://www.therundown.ai/tools/replit-agent-4)

### Inferences
- The strongest documented pattern is "generator never grades itself": separate evaluator agent with clean context, ideally a different model, with a hard pass threshold and browser access for UI. An engine can enforce this deterministically (Stop hook / CI gate) rather than trusting the worker's claim.
- "Evidence, not assertion" (command + output or screenshot attached to the report) is the cheapest verification upgrade and is what Claude Code's docs recommend for unattended sessions.

### Gaps
- No primary documentation found for how Codex cloud validates work beyond test execution and citations in the task log (the docs host was unreachable).
- Devin's documented verification mechanics (browser use, test running) were not reachable; only Devin Review numbers via Cognition's blog.

## KQ3. How does each handle the PR lifecycle (open, CI failures, review comments, iterate to merge)?

### Takeaway
All hosted agents open a branch + (draft) PR and accept follow-ups by `@mention` in PR comments; only a few subscribe to PR events to react on their own (Claude "Auto-fix", Jules CI-fix and PR-comment mode, Copilot `@copilot`). Codex's CI auto-fix is not native (issue closed "not planned"; community GitHub Actions do it), and no agent reacts to merge conflicts from base-branch advances because GitHub emits no webhook for that.

### Cited Findings
- Claude Auto-fix: "Claude subscribes to GitHub activity on the PR, and when a check fails or a reviewer leaves a comment, Claude investigates and pushes a fix if one is clear"; "Ambiguous requests ... Claude asks you before acting"; "GitHub does not emit a webhook when the base branch advances and creates a merge conflict, so auto-fix can't react to conflicts on its own"; replies "are posted using your GitHub account ... labeled as coming from Claude Code"; warning that replies can trigger `issue_comment` automations (Atlantis, Terraform Cloud); enable via `/autofix-pr` in terminal, the Changes card, or mobile — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Claude scheduled tasks can trigger on `pull_request.opened`/`closed` etc. with filters (author, title, body, base/head branch, labels, is draft, is merged); example "Library port: a GitHub trigger runs on `pull_request.closed` filtered to merged PRs" — [Claude Code docs: scheduled tasks](https://code.claude.com/docs/en/routines)
- Copilot: "regularly pushes its changes to a draft pull request as git commits and updates the pull request's description. When it finishes, it'll tag you for review"; "GitHub Actions workflows won't run without your approval" — [GitHub Blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/); correct a run by "Mentioning @copilot in a PR comment" (secondary) — [adamtheautomator](https://adamtheautomator.com/github-copilot-agent-mode-vs-cloud-agent/)
- Codex: `@codex review`, `@codex fix the P1 issue`, `@codex fix the CI failures` are documented comment commands — [OpenAI Codex docs: GitHub integration](https://developers.openai.com/codex/integrations/github); feature request "Add CI auto-fix feature" noted `@codex fix` "doesn't have access to the workflow logs" and was closed not planned — [openai/codex #9481](https://github.com/openai/codex/issues/9481); automatic reviews failing/silently not triggering reported Oct 2026 — [openai/codex #57619](https://github.com/openai/codex/issues/57619), [#15477](https://github.com/openai/codex/issues/15477); OpenAI cookbook shows a GitHub Actions recipe "Use Codex CLI to automatically fix CI failures" — [OpenAI cookbook](https://developers.openai.com/cookbook/examples/codex/autofix-github-actions)
- Jules: "When a check fails in GitHub Actions, Jules receives the error, works through a fix, and resubmits the PR" and "only fixes PRs it has created"; "Based on your feedback, Jules will then push a commit with the requested changes", with a reactive mode acting only on `@Jules` mentions — [Jules changelog](https://jules.google/docs/changelog/); "Jules now acts on your PR feedback" — [Jules on X](https://x.com/julesagent/status/1970640318606258605)
- Cursor: agent "pushes its branch and opens a draft pull request for a human to review before anything merges" — [Cursor docs: security](https://prod.cursor.com/docs/cloud-agent/security)
- OpenHands: apply the `fix-me` label or comment `@openhands-agent` to start the resolver — [OpenHands docs: GitHub action](https://docs.openhands.dev/usage/how-to/github-action)
- Ona agents "open pull requests, and respond to review feedback" (secondary) — [ai-deck](https://ai-deck.app/blog/ona/)
- Empirical merge outcomes (2026): agent PRs merged "roughly 65% versus about 85% for human PRs", per-agent "43% for Devin to 84% for Claude Code, with Codex at 73%" (AIDev dataset, secondary summary) — [Robert Stowe](https://robertstowe.com/agent-pull-requests-merge-at-65-humans-at-85/); LinearB: AI-assisted PRs merged within 30 days 32.7% vs 84.4% unassisted — [LinearB](https://linearb.io/library/ai-in-software-development); Microsoft: CLI-agent users merged ~24% more PRs, revert rates fell, but AI PRs took ~20% longer to merge after first review — [TechRepublic](https://www.techrepublic.com/article/news-ai-coding-agents-microsoft-pull-requests/); repo popularity confounds: 73.67% merge in 100+ star repos vs 90.63% elsewhere — [IJRASET](https://www.ijraset.com/best-journal/ai-coding-agents-on-github-repository-popularity-as-a-hidden-confounder-in-the-acceptance-of-2-million-agentauthored-pull-requests)

### Inferences
- An engine should own the PR event subscription itself (webhook → new session with PR head checkout), treat each event as a fresh session (as Claude scheduled tasks do), label agent-authored comments, and explicitly handle the "base advanced / conflict" case by polling because no webhook exists.
- Human review capacity, not agent throughput, is the merge bottleneck across all 2026 studies; digest-style reporting and small PRs matter more than raw parallelism.

### Gaps
- No documented behaviour found on how Devin or Factory respond to CI failures (docs hosts unreachable).
- Per-agent merge-rate figures come from one secondary summary of an academic dataset; the primary paper's headline numbers were not retrieved.

## KQ4. How do they plan and manage long tasks (spec/plan approval, decomposition, subagents, compaction, checkpoints, handoff)?

### Takeaway
Plan-then-approve is now universal (Claude plan mode, Codex/Factory spec mode, Devin Interactive Planning with an "Agency" setting, Jules plan with critic). For long runs the field split on context handling: Claude and OpenHands compact in place (with hooks/condensers), Amp moved from compaction to explicit "handoff" into a fresh thread, and Anthropic's harness research uses structured artifact handoffs between fresh agents; Cognition argues writes must stay single-threaded while extra agents only add intelligence.

### Cited Findings
- Claude plan mode: "Claude reads files, runs commands to explore, and proposes a plan without editing source code"; recommended "Plan locally, execute in the cloud" by committing the plan file — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md); SDK `permissionMode: "plan"` "file edits are never auto-approved" — [Agent SDK: agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop.md)
- Agent teams: teammates spawned while the lead is in plan mode "work in read-only plan mode until its plan is ready", then send a plan approval request; "Task claiming uses file locking"; tasks can depend on others and "shows as blocked"; hooks `TeammateIdle`, `TaskCreated`, `TaskCompleted` (exit code 2 blocks); guidance "Start with 3-5 teammates", "5-6 tasks per teammate" — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams.md)
- Claude compaction: cloud sessions set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` so compaction "triggers partway through the auto-compact window"; teleported sessions continue "from the summary" — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md); SDK emits `compact_boundary`, `PreCompact` hook can "archive the full transcript", CLAUDE.md can carry "Summary instructions" the compactor honours; `session_store`/`sessionStore` adapter resumes "across stateless containers or serverless hosts" — [Agent SDK: agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop.md)
- Anthropic harness research: resets ("clearing the context window entirely and starting a fresh agent, combined with a structured handoff") were needed for Sonnet 4.5 which showed "context anxiety", but were dropped for Opus 4.5 in favour of automatic compaction; planner "stays high-level on purpose, since if the planner tried to specify granular technical details upfront and got something wrong, the errors in the spec would cascade"; recommends "removing harness components that stop being load-bearing as models improve" — [Anthropic: Harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps)
- Cursor scale design: "Planners continuously explore the codebase and create tasks. They can spawn sub-planners... Workers pick up tasks and focus entirely on completing them. They don't coordinate with other workers"; "With no hierarchy, agents became risk-averse. They avoided difficult tasks and made small, safe changes"; locking caused "Twenty agents would slow down to the effective throughput of two or three"; "Planners should ideally wake up when their tasks complete ... this reactive coordination isn't fully implemented" — [Cursor blog](https://cursor.com/blog/scaling-agents); [ZenML summary](https://www.zenml.io/llmops-database/scaling-multi-agent-autonomous-coding-systems)
- Cognition 2025 (historical): "Don't Build Multi-Agents" (2025-06-12) — share context and full agent traces, parallel sub-agents are fragile — [Cognition](https://cognition.com/blog/dont-build-multi-agents); 2026 update: multi-agents "work best today when writes stay single-threaded and the additional agents contribute intelligence rather than actions"; "the sub-agent-to-manager communication pattern doesn't happen by default, because models haven't been trained in environments where it needed to" — [Cognition: Multi-Agents, What's Actually Working](https://cognition.com/blog/multi-agents-working)
- Amp: `/handoff` "starts a new thread with context from the current one"; Amp "drafts a prompt and lists relevant files, which you can edit before starting"; the agent can also hand off mid-task on its own — [Amp: Handoff, Please](https://ampcode.com/news/ask-to-handoff); framed as replacing compaction to fix long-context drift (secondary) — [Tessl](https://tessl.io/blog/amp-retires-compaction-for-a-cleaner-handoff-in-the-coding-agent-context-race) (a conflicting secondary review claims Amp moved to compaction — unresolved)
- Devin: "Interactive Planning" researches the repo and proposes an editable plan; "you can choose whether Devin requires your approval before executing a plan (via the Agency setting) or runs fully autonomously" (secondary) — [easycoding.tools](https://easycoding.tools/blog/en/inside-devin-s-workflow-tool-use-planning-and-autonomy); "Devin Manages Devins" coordinator "scopes the work, tracks progress, handles conflicts, and assembles the results" — [Devin release notes 2026](https://docs.devin.ai/release-notes/2026)
- Factory spec mode: `--use-spec` or Shift+Tab; "Droid researches and plans without edits or command execution, then waits for approval before implementing" — [Factory docs: CLI reference](https://docs.factory.ai/reference/cli-reference)
- Codex plan mode "writes out a proper implementation plan, and once you've signed it off, it goes and executes" (secondary) — [composio](https://composio.dev/content/claude-code-vs-openai-codex)
- Copilot CLI lowered "default maximum sub-agent nesting depth from 6 to 4" (v1.0.71) — [copilot-cli release](https://github.com/github/copilot-cli/releases/tag/v1.0.71); cloud agent "no longer limited to pull-request workflows", sessions can plan/research without a PR — [GitHub Community #190573](https://github.com/orgs/community/discussions/190573)
- OpenAI harness engineering (2026-02-11): "give Codex a map, not a 1,000-page instruction manual" after a single huge AGENTS.md failed; enforce invariants ("parse data shapes at the boundary") rather than micromanage; repo as "single system of record"; Friday "AI slop" cleanup (20% of the week) moved into "background Codex tasks that scan for drift and open small refactoring pull requests"; cache misses when tools/model/sandbox/cwd change mid-conversation (secondary summaries) — [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/); [ignorance.ai](https://www.ignorance.ai/p/the-emerging-harness-engineering)
- Cohere: well-organized agent teams beat solo agents "up to ~10 percentage points on ProgramBench" at ~30% of the cost (headline) — [Cohere blog](https://cohere.com/blog/lessons-from-scaling-teams-of-frontier-coding-agents)

### Inferences
- A self-hosted engine should implement: plan artifact committed to the repo → approval gate → execution session; single writer per branch (or per-file ownership) with reviewers as read-only "intelligence" agents; deterministic hooks (`Stop`, `TaskCompleted`) as quality gates; archive full transcripts before compaction; explicit handoff documents when a session is restarted.
- Hierarchy (planner/worker) is needed mainly to fight risk-aversion and to keep worker context small; the open problem everyone reports is reactive wake-up of the planner when tasks finish.

## KQ5. How do they report to the human and ask questions?

### Takeaway
Reporting converged on: the PR description + a structured final summary (files changed, runtime, branch), event-driven notifications (desktop/mobile push when a thread posts, errors, or needs input), and explicit "ask before acting" rules for ambiguous review comments. Questions are posed in-session and the session waits (Claude keeps the answer slot open until environment expiry; Devin sleeps after 30 minutes idle and consumes nothing).

### Cited Findings
- Claude Projects: coordinator "sees what threads report back, not every step they take"; threads "report back to the conversation when it finishes"; "See what needs you in Overview"; desktop notification "when Claude posts in the conversation, a thread hits an error, or a thread needs your input", optional per-turn notifications; instructions should say "what needs your go-ahead"; troubleshooting section "Threads guessed or stalled instead of asking" — [Claude Code docs: Projects](https://code.claude.com/docs/en/claude-projects.md)
- Claude cloud: "If Claude asks a question and the session sits idle, you can still answer when you come back, up to environment expiry"; auto-fix: "Ambiguous requests ... Claude asks you before acting"; "Duplicate or no-action events: ... Claude notes it in the session and moves on" — [Claude Code docs: cloud](https://code.claude.com/docs/en/claude-code-on-the-web.md)
- Scheduled tasks: run status "Succeeded: the session ended without Claude Code reporting a failure. Blocked network requests, missing connector tools, and work Claude couldn't complete appear in the transcript rather than on the row"; example tasks "post a summary to Slack"; `/schedule why did my nightly review do nothing this morning?` reads the run log to explain "tool errors, permission denials, and the final result"; API fire `text` payload is wrapped as "untrusted data" the prompt must opt in to act on — [Claude Code docs: scheduled tasks](https://code.claude.com/docs/en/routines)
- Agent SDK tools include `AskUserQuestion`; `permissionMode: "dontAsk"` "Never prompts ... Every call that would otherwise prompt is denied" for "Headless agents with nobody to approve calls" — [Agent SDK: agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop.md)
- Agent teams: "when a teammate finishes and stops, it automatically notifies the lead and includes its final answer"; teammate permission prompts "appear in the lead session"; messages between agents are flagged as from "another Claude session, not from you" and "A teammate can't approve a permission prompt" — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams.md)
- Copilot: "When it finishes, it'll tag you for review and you can leave comments asking for it to make changes" — [GitHub Blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)
- Jules final summary lists "Files changed, runtime, lines changed, and the branch name and commit message" — [Jules docs: reviewing code changes](https://jules.google/docs/code/)
- Devin: "Devin sleeps automatically after 30 minutes of inactivity by default. Lite sessions and sessions created through the API ... sleep after 5 minutes"; enterprise timeout 5-120 minutes; "Devin does not consume any usage while sleeping" — [Devin docs: usage](https://docs.devin.ai/admin/billing/usage)
- Cursor: follow-ups from Slack/GitHub/Linear "queue behind the current run, or interrupt it on request" — [Cursor docs: BDK](https://cursor.com/docs/bdk/guides/cloud-agents)
- Claude Code general guidance: "Be concise" is echoed in docs ("short, plain-English summaries") and the harness blog advice to ask for evidence — [Claude Code docs: best practices](https://code.claude.com/docs/en/best-practices)

### Inferences
- A good engine distinguishes three outbound message classes: needs-input (blocking, push notification), finished (summary + evidence + PR link), and informational (transcript only). Claude's "Succeeded but see transcript" status shows that success/failure rows alone hide partial failures; the engine should surface "couldn't complete" items in the digest.
- Idle-while-waiting should cost nothing (Devin sleep) and the answer slot should persist (Claude) — i.e., questions are durable state, not a live prompt.

### Gaps
- No documented "structured question" schema (multiple-choice etc.) found for Codex, Cursor, Jules or Devin in reachable sources.
- No published "silence rules" (when not to notify) beyond Claude's optional per-turn notifications.

## KQ6. What do they cost per task and how do they bound cost/time?

### Takeaway
Pricing has settled into three shapes: flat per-session premium requests (Copilot: 1 premium request/session plus Actions minutes), compute units with hard per-session caps (Devin ACUs, ~10 ACU guidance, admin caps), and subscription-pooled usage with explicit per-run cost limits in the SDK (`maxTurns`, `maxBudgetUsd`). Wall-clock bounds are the common hard stop: Copilot 59 min, Vercel-hosted Cursor 45 min, Claude bash 2-10 min per command and idle VM pausing, Jules per-tier daily task caps.

### Cited Findings
- Copilot: "one premium request per session, multiplied by the model's rate"; "the GitHub Actions minutes used will still vary" — [GitHub Changelog 2025-07-10](https://github.blog/changelog/2025-07-10-github-copilot-coding-agent-now-uses-one-premium-request-per-session/); "59-minute maximum execution time per cloud agent session" (community) — [GitHub Community #199770](https://github.com/orgs/community/discussions/199770); Copilot SDK sessions can set an "AI Credits budget"; CLI v1.0.67 "requires session limits to be at least 30 AI credits" — [copilot-cli v1.0.67](https://github.com/github/copilot-cli/releases/tag/v1.0.67)

## KQ7. Published failure modes and lessons from the teams

### Takeaway
The repeated 2026 lessons: self-review in the same context skews positive; without hierarchy agents become risk-averse; locking kills parallel throughput; prompt wording matters more than architecture; giant instruction files fail (use a map + invariants); merge-review capacity is the real bottleneck; and harness components should be removed as models improve.

### Cited Findings
- Cursor: "A surprising amount of the system's behavior comes down to how they prompt the agents"; "Agents occasionally run for far too long without making meaningful progress"; GPT-5.2 "much better at extended autonomous work: following instructions, keeping focus, avoiding drift" and "a better planner than GPT-5.1-Codex" — [Cursor blog](https://cursor.com/blog/scaling-agents); [ZenML](https://www.zenml.io/llmops-database/scaling-multi-agent-autonomous-coding-systems)
- Anthropic: "models tend to lose coherence on lengthy tasks as the context window fills"; "context anxiety ... wrapping up work prematurely"; "agents reliably skew positive when grading their own work"; evaluator tuning "required reading its logs, finding where its judgment diverged from the author's, and revising its prompt over several rounds"; planner "under-scoped when run without the evaluator" — [Anthropic: Harness design](https://www.anthropic.com/engineering/harness-design-long-running-apps); earlier "Effective harnesses for long-running agents" (Nov 2025, historical) referenced by [InfoQ](https://www.infoq.com/news/2026/04/anthropic-three-agent-harness-ai/)
- Cognition: parallel-writer swarms still fail ("Our original observations still hold today for parallel-writer swarms"); single-writer + intelligence-only helpers work — [Cognition](https://cognition.com/blog/multi-agents-working)
- OpenAI: single large AGENTS.md failed → "map"; weekly "AI slop" cleanup automated into background drift-fixing PRs; "the bottleneck was the lack of structure, tools, and feedback mechanisms surrounding the agent, not its ability to write code" (secondary) — [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/); [datasciencedojo](https://datasciencedojo.com/blog/harness-engineering/)
- Claude Code docs: "Agents stopping early: Teammates may stop after encountering errors instead of recovering"; "The lead can stop early too"; "Task status can lag: teammates sometimes fail to mark tasks as completed, which blocks dependent tasks"; "Letting a team run unattended for too long increases the risk of wasted effort" — [Claude Code docs: agent teams](https://code.claude.com/docs/en/agent-teams.md); "If you keep adding emphasis to a `CLAUDE.md` line and Claude still misses it, that's a sign the line belongs in a hook"; "A reviewer that's asked to find problems will always find *something*"; "keep the enforced set small ... If you ever find yourself at forty of them, most are probably preferences" — [Claude Code docs: best practices](https://code.claude.com/docs/en/best-practices)
- Worktree isolation is weaker than assumed ("if you are running multiple coding agents in parallel using git worktrees... you do not actually have isolation" — shared services/ports/DBs) (HN summary, secondary) — [TerminalBlog](https://terminalblog.com/blog/coding-agents-three-hard-lessons-hn-developers/)
- Copilot self-review praises quick fixes (user review, secondary) — [Sean Kim](https://blog.imseankim.com/github-copilot-coding-agent-3-months-model-picker-self-review-cli-handoff-review/)
- Codex automatic PR reviews failing in 1-4 s / silently not triggering (Oct 2026 issues) — [openai/codex #57619](https://github.com/openai/codex/issues/57619)
- OpenHands: no escalation ladder — "the critic retries the same model rather than switching to a stronger one" — [software-agent-sdk #5615](https://github.com/OpenHands/software-agent-sdk/issues/5615)
- Jules: added tests PR reverted after "persistent, uninformative RuntimeExceptions" — [neurhome #175](https://github.com/carlo-colombo/neurhome/pull/175)
- Review bottleneck: Harvard/Jellyfish coverage "+30% code, +23% PRs, merge time +49%" (secondary, unconfirmed primary) — [explainx](https://explainx.ai/blog/ai-coding-agents-more-code-not-more-software-harvard-jellyfish-review-bottleneck-2026); GitHub CAIS 2026 talk on "about 200 daily agents" built as "repository automation on top of GitHub Actions and Copilot CLI" — [CAIS 2026 workshop](https://agenticse-cais.github.io/)
- "10 Lessons for Agentic Coding" (May 2026) — headline "the hard work is where the value is"; full list not retrievable — [dbreunig](https://www.dbreunig.com/2026/05/04/10-lessons-for-agentic-coding.html)
- Confucius Code Agent paper: "principled scaffolding can substantially amplify the effectiveness of the same underlying LLM" — [arXiv 2512.10398](https://arxiv.org/html/2512.10398v6)

### Inferences
- Deterministic enforcement (hooks, deny rules, CI gates) beats prompt emphasis; every vendor doc now says so explicitly. Neo's "rules live in code" principle is aligned with the field.
- Expect and design for: stalled teammates (watchdog + re-dispatch), stale task status (verify completion by artifact, not by claim), and early stop by the coordinator (goal-checked loops).
